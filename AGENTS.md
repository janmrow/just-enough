# Working on Just Enough

These instructions guide edits to this repository. They do not define how an agent using the installed skill should answer a user's task.

## Preserve the skill

`SKILL.md` is the source of truth for the skill's behavior. Keep its meaning, activation conditions, safeguards, stopping rule, and freedom of response intact. Presentation work should not require changes to it.

The project's literary and visual identity belongs to its presentation. Do not turn it into a persona, a poetic response style, a required vocabulary, or a fixed answer format. An agent using Just Enough should follow the user's task and its own normal style.

## Write with measure

Use contemporary US English. Be calm, concrete, natural, and lightly warm.

- Put the useful point first.
- Prefer precise nouns and active verbs.
- Give each paragraph one purpose. Vary sentence length to keep a natural rhythm.
- Keep terminology stable: complexity, value, constraints, enough.
- Use a small amount of imagery in presentation copy. Keep instructions, commands, technical documentation, and examples literal.
- Favor clarity over cleverness. Avoid grand claims, forced humor, mystical language, and decorative jargon.
- Describe what complexity contributes as well as what it costs. A recommendation to keep the current approach is a valid outcome.

Write **Just Enough** in prose and `just-enough` in commands, paths, and identifiers.

The shared tagline is **Find enough in a world of more.** The plain description is **An AI skill for deciding which complexity earns its place.**

## Keep the visual identity coherent

Use warm paper, charcoal ink, restrained gray, and a small muted red accent. Favor one botanical ink motif, generous space, and an asymmetric composition. The artistic references are classical Chinese and Japanese painting, calligraphy, and haiku. Keep the presentation secular.

Use Source Serif 4 and Source Sans 3 in artwork. README body text uses GitHub's native typography. Keep important instructions as selectable text.

## Be exact about evidence

Label constructed examples as illustrative. Attribute personal experience to the maintainer. Publish measured claims only with their method and underlying results. Do not turn an illustrative before-and-after into a claim about a recorded run.

## Finish with the useful checks

Check relative links, image paths, installation instructions, and readability on a narrow screen and in both GitHub themes. For a presentation-only change, confirm that `SKILL.md` and `LICENSE` remain unchanged. Avoid adding processes, dependencies, or documents that the change does not need.
